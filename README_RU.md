Браузерное расширение, которое предупреждает **в момент, когда вы собираетесь ввести пароль** на странице, похожей на подделку. Модель обучена на 886 181 реальном URL, весит 748 КБ, лежит внутри расширения и считает адрес за **0,04 мс на вашем процессоре**. В коде нет ни одного сетевого запроса — отдельный тест читает исходники и падает, если в них появится `fetch`, `XMLHttpRequest`, `eval` или `importScripts`.

```text
URL -> 30 признаков -> 299 деревьев -> вероятность -> баннер над полем пароля
```

## Зачем это нужно

Точность — не самая трудная часть задачи. При **recall 53% на 1% ложных срабатываний** проверка каждой открытой страницы дала бы миллионы алертов в день, и такое расширение никто не держит дольше часа. Поэтому продукт построен не вокруг модели, а вокруг **условия, при котором модель вообще спрашивают**:

> Расширение молчит, пока вы читаете. Оно говорит только тогда, когда страница готова получить учётные данные: появилось поле пароля или нажат «Войти».

Это сужает население страниц, на которых модель оценивается, на три порядка — и при таком отборе 53% recall достаточно, чтобы ловить больше половины атак, не мешая жить.

Чем это осознанно **не** является:

- **Не нейросеть.** Бустинг из 299 деревьев — это 748 КБ целых чисел, а инференс — цикл `while`. Трансформер здесь стоил бы 40 МБ, WASM и 5 мс, чтобы ответить на тот же вопрос по тем же 30 числам.
- **Не облачный API.** Ни ключей, ни лимитов, ни уходящего наружу URL. Проверка фишинга, которая звонит домой, — это уязвимость приватности, приделанная к защитному продукту.
- **Не блоклист.** Блоклист знает вчерашние домены; модель обобщает по форме строки (`paypa1`, `sberbank-online-verify.ru`, `…/account/confirm?session=…` на бесплатном хостинге).

## Измеренные результаты

Разбиение **по доменам**, а не случайное: `blake2b(eTLD+1) % 5 == 0` уходит в тест. Пересечение доменов между train и test — ровно ноль, то есть модель не видела даже соседние страницы того же сайта.

| метрика | групповой сплит (честный) | случайный сплит (для сравнения) |
| --- | ---: | ---: |
| ROC-AUC | **0.9407** | 0.9622 |
| PR-AUC | **0.9022** | — |
| recall @ 1% FPR | **0.533** | 0.646 |
| recall @ 5% FPR | **0.738** | — |

Разница в 2 пункта AUC между двумя сплитами — это цена утечки: при случайном сплите почти та же страница попадает и в обучение, и в тест. Все цифры выше читаются из `build/report.json`; в отчёте цитируется нижняя строка.

| | |
| --- | --- |
| данные | 886 181 URL, из них 275 349 фишинговых (`Mitake/PhishingURLsANDBenignURLs`) |
| модель | LightGBM, 299 деревьев, 31 лист, 9.5 с на обучение на CPU |
| размер | 748 КБ JSON, без зависимостей и без WASM |
| скорость | 38–42 мкс на URL (признаки + все деревья, один поток, Node 24) |
| паритет train↔serve | признаки: **0.0**, вероятности: **2.8e-6** на 2 000 URL |
| инвариант объяснения | `raw = base + Σ contrib` выполняется с точностью **0.0** |

## Как это устроено

**1. Тридцать признаков из одной строки URL.** Никаких DNS и сети: длина домена и пути, энтропия, число цифр и дефисов, punycode, голый IP, порт, бесплатные хостинги (`vercel.app`, `gitbook.io`, `workers.dev`…), слова `login` / `verify` / `wallet`, и главное — **подмена букв цифрами**: `paypa1` даёт `paypal`, `g00gl3` даёт `google`.

**2. Бустинг, экспортированный в плоские массивы.** Инференс в `src/engine.js` — примерно двадцать строк `while`. Градиентный бустинг хранит базовое смещение вне деревьев, поэтому при экспорте оно восстанавливается в `init_score` — иначе браузер выдавал бы другую вероятность, чем Python.

**3. Объяснение — это арифметика, а не догадка.** `engine.js` возвращает вклад каждого признака, потому что `raw = base + Σ contrib` точное. Попап показывает, что именно толкнуло вердикт; `tests/parity.mjs` перепроверяет тождество на всех 2 000 URL.

**4. Правила поверх модели.** Два сигнала, которых в строке URL нет: форма с паролем на странице без HTTPS и название бренда в заголовке страницы, которого нет в домене. Сами по себе они не срабатывают — только повышают уже полученный уровень, а домен, разрешённый пользователем, перекрывает их все.

**5. Паритет train↔serve как гейт.** Признаки написаны дважды: `train/features.py` и `src/features.js`. `tests/parity.mjs` прогоняет 2 000 реальных URL через обе реализации и падает при любом расхождении больше 1e-6. Здесь оно ровно ноль.

## Установка

1. Открыть `chrome://extensions` и включить **Режим разработчика**.
2. **Загрузить распакованное** → выбрать папку `phishguard/`.
3. Открыть любой сайт: в бейдже будет `!!` (опасно), `!` (подозрительно) или пусто. Клик по иконке — вероятность и список причин.

## Проверить самому

```bash
node tests/parity.mjs     # паритет Python <-> JS, инвариант объяснения, латентность
node tests/rules.mjs      # 35 проверок поведения на фейковом chrome API
node scripts/score.mjs "https://paypa1-secure-login.vercel.app/account"
node demo/serve.mjs       # http://localhost:8731/ — четыре локальных сценария
```

`tests/rules.mjs` подставляет фейковый `chrome` в `globalThis` до импорта service worker'а, а затем проверяет то, что видит пользователь: эскалацию по содержимому страницы (пароль без HTTPS → опасно, бренд в заголовке при чужом домене → подозрительно, пароль + карта → опасно), разрешённые домены, текст и цвет бейджа, восстановление состояния после перезапуска service worker и очистку `tabState` при закрытии вкладки. Отдельная статическая проверка читает `src/*.js` и падает на любом сетевом примитиве.

Три бага, которые эти тесты поймали сразу:

1. Разрешённый домен всё равно получал «опасно», потому что правило про HTTP перекрывало решение пользователя. Теперь явное разрешение сильнее всех правил.
2. `tabState` рос до перезапуска браузера — не было обработчика `tabs.onRemoved`.
3. После перезапуска service worker попап показывал «не проверялось» на любой вкладке. Теперь он спрашивает у вкладки адрес и считает заново.

## Демо без посещения фишинга

`node demo/serve.mjs` отдаёт на 127.0.0.1 четыре сценария: страница без полей (расширение должно молчать), форма входа по HTTP, страница с заголовком PayPal и форма с паролем и картой. Индексная страница печатает вероятности, посчитанные тем же движком, что работает внутри расширения, — таблица не нарисована руками.

Одна честная особенность: `localhost` и голые IP модель считает опасными. Она права в том смысле, что такие адреса редки у нормальных сайтов и часты в обучающих данных как фишинг. Поэтому демо — это ещё и упражнение на кнопку «Это мой сайт, больше не предупреждать»: после неё расширение замолкает на этом домене полностью, включая правила.

## Переобучить

```bash
uv sync --locked
uv run python train/train.py
node tests/parity.mjs
```

`train/train.py` скачивает данные отдельно (`data/raw.csv`), кэширует матрицу признаков в `data/features.npz` и пишет `build/report.json`, `build/model.json`, `src/model.js` и `tests/features_py.json` для гейта паритета.

## Что не работает

- **Только URL.** Если злоумышленник поставил фишинг на взломанный настоящий домен (`pennpilates.com/accnotify/index.php` — такие строки есть в данных), строка адреса выглядит нормально. Ровно для этого нужны правила по содержимому страницы, и они пока очень грубые.
- **Свой бренд на своём домене** тоже получает завышенный скор: `sberbank.ru` даёт 0.70, потому что длина домена и слова в пути у него те же, что у подделок. В расширении это лечится разрешённым списком, в модели — нет.
- **Нет проверки сертификата, возраста домена, WHOIS.** Браузер не даёт этих данных без сетевого запроса, а сетевой запрос — это уже не «локально и бесплатно».
- **Русскоязычный фишинг почти не представлен** в обучающем наборе: 886 тысяч URL в основном англоязычные. Для СНГ-сегмента цифры будут хуже.

## Структура репозитория

```text
manifest.json          MV3, service worker как ES-модуль
src/features.js        30 признаков (зеркало features.py)
src/engine.js          инференс леса + точное аддитивное объяснение
src/model.js           выгруженные веса, 748 КБ
src/background.js      единственное место, где считается модель
src/content.js         ловит момент ввода пароля и рисует баннер
src/popup.html/js      вероятность, причины, разрешённые домены
train/features.py      признаки для обучения
train/train.py         обучение, метрики, экспорт
tests/parity.mjs       гейт паритета train<->serve
tests/rules.mjs        35 проверок поведения (фейковый chrome API)
tests/features_py.json 2 000 эталонных строк, пишет train.py
scripts/score.mjs      CLI: оценка произвольного URL
demo/serve.mjs         локальные сценарии для демонстрации
```
